Depende de cómo esté configurado el servidor en ese dispositivo; por defecto, no es posible si realmente está solo en localhost. Para que puedas acceder, deben cumplirse varias condiciones de red: 1. Dónde está escuchando el servidor Solo en localhost / 127.0.0.1: Es la interfaz de loopback. El sistema operativo del otro dispositivo solo acepta peticiones que provengan de su propia máquina y rechaza automáticamente cualquier intento de conexión desde fuera. Escuchando en 0.0.0.0 o su IP local: Si el servidor se levantó configurado para escuchar en todas las interfaces de red (habitual con comandos como npm run dev -- --host, python -m http.server, o frameworks configurados con host 0.0.0.0), el puerto sí queda abierto para la red local compartida. 2. Reglas del Firewall Los sistemas operativos de escritorio (como Windows Defender Firewall o el cortafuegos de macOS) suelen clasificar la conexión del punto de acceso móvil como una red pública y bloquean por defecto todas las conexiones entrantes a puertos no explícitamente permitidos. 3. Aislamiento de clientes (AP Isolation) Algunos sistemas operativos móviles implementan aislamiento de clientes en la zona Wi-Fi compartida, lo que impide que los dispositivos conectados se comuniquen directamente entre sí, permitiendo únicamente el tráfico de subida y bajada a Internet.
